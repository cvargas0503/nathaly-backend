# F04 — Auditoría de catálogos

Issue #6. Servicio compartido integrado solamente en Categoria, Marca y Linea. Permisos GESTIONAR_CATEGORIAS/MARCAS/LINEAS siguen protegiendo escrituras. Lectura `/api/v1/auditoria` requiere `VER_AUDITORIA_CATALOGOS`; aplicar 005_f04_auditoria.sql y asignarlo desde administración.

Crear genera CREAR con anterior NULL. Editar nombre genera MODIFICAR con ambos snapshots. Eliminar lógicamente genera ELIMINAR y conserva nombre y metadatos. Entidades canónicas: categorias, marcas, lineas. Cambio y evento comparten EntityManager/transacción. Se serializan escritores de cada catálogo con un lock de aplicación; fallo de auditoría revierte el catálogo. Se ignoran cambios de metadatos suministrados por el cliente: la entrada mutable es nombre, normalizado a mayúsculas. Actualización del mismo nombre normalizado no agrega evento ni cambia metadata. Lotes generan un evento por registro activo; registros ya eliminados no generan otro evento.

Campos permitidos en snapshots: ID de la entidad, nombre, eliminado, creadoPor, fechaCreacion, modificadoPor, fechaModificacion, eliminadoPor, fechaEliminacion. Excluidos: request/body completo, cookies, tokens, contraseñas, encabezados, campos desconocidos. Usuario y login proceden de sesión; fechas UTC. No hay logs del request en handlers intervenidos. No se publican escrituras ni borrados de auditoría.

GET admite entidad, accion=CREAR/MODIFICAR/ELIMINAR, usuarioId, desde, hasta, page, limit e incluirDatos=true/false. Fechas UTC ISO 8601 y rango inclusivo válido. Paginación 20 por defecto/máximo 100, fecha/ID descendente. Filtros combinables parametrizados. incluirDatos=false omite JSON; true devuelve snapshots como objetos/null. `fuente=persistida` identifica los eventos reales. Se mantiene success/message/data y agrega pagination.

Se elimina la reconstrucción silenciosa ante errores: toda lectura depende de ADMIN.Auditoria. Una BD no disponible produce 500; no se inventa historia anterior. Los eventos históricos reales existentes permanecen. No se fabrican eventos de catálogos anteriores a la activación. 400: filtros/entrada; 401/403: sesión/permiso; 404: registro ausente; 409: nombre duplicado/formato de BD; 500: persistencia. Las lecturas existentes de catálogos se conservan. Eliminación repetida sin registros activos devuelve count=0, sin evento.
